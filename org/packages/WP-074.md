# Work package: WP-074

- **State:** READY
- **Owner (role):** Lead-tier lane, storage · **Model:** Claude Opus 5.5 or
  gpt-6-sol (record the one selected in `status/WP-074.md`)
- **Base revision:** master @ 00048dc
- **Intent:** DESIGN.md, Write Conflicts and Read Path: conflict detection
  must not cost a full download, and the sync path must never record a
  member as holding content it does not. Serves the sprint-1 schwerpunkt
  (write/sync path correctness and cost). GitHub #74 was the most expensive
  behavior observed in real use: multi-gigabyte `copy_to_local` calls with
  no process asking for them, competing with streaming prefetch.
- **Instruction:** (1) `ConflictDetector.check_conflict` compares the
  member's checksum obtained through `backend.get_fast_checksum` instead of
  downloading the file to a temp path and hashing it locally; the download
  fallback is the backend's concern (`SSHBackend.get_fast_checksum` already
  falls back when `xxh128sum` is absent on the remote). (2) In
  `SyncExecutor.process_file_task`, `add_file_location` is recorded only
  after the final publish succeeds, so a refused pass (a write landed during
  the copy) leaves no checksum for content the member does not hold
  (ditz `refused-pass-stale-location-checksum`).
- **Non-goals:** no change to conflict *resolution* (`storage conflicts`),
  no new checksum algorithm, no change to streaming.
- **Owned scope:** `storage/conflicts.py`, `storage/sync_executor.py`, their
  tests (`tests/test_conflicts_integration.py`, `tests/test_sync_executor.py`,
  a new conflict-detector unit test module listed in BUILD), README Status
  if a user-visible behavior changes.
- **Dependencies:** `Backend.get_fast_checksum` (published on
  `storage/backends/base.py`); `StateManager.publish_sync_status` and the
  generation rule in AGENTS.md (merged in #97).
- **Acceptance criteria:** a conflict check against a member whose
  `get_fast_checksum` succeeds never calls `copy_to_local` (a counting fake
  backend proves it); a member without a fast checksum still gets a correct
  conflict verdict; a sync pass refused at publish leaves no
  `file_locations` row for that member; a successful pass records the row
  with the checksum of the content copied; every test added to pin a fix is
  mutation-checked (revert the fix, watch it fail) before the round closes.
- **Boundary tests:** `tests/test_conflicts_integration.py` (real mount)
  must keep passing unchanged.
