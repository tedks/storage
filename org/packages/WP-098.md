# Work package: WP-098

- **State:** READY
- **Owner (role):** Lead-tier lane, storage · **Model:** Claude Opus 5.5 or
  gpt-6-sol (record in `status/WP-098.md`)
- **Base revision:** master @ 00048dc
- **Intent:** DESIGN.md, Write Path: every write reaches its configured
  replicas eventually. GitHub #98: a row left at SYNCING by a crash or by a
  rename mid-sync is never requeued, because the monitor scans DIRTY only.
  Serves the sprint-1 schwerpunkt.
- **Instruction:** (1) At mount, before the sync manager starts (in
  `StorageFS.init()`, post-fork), move every SYNCING row to DIRTY through a
  generation-safe StateManager method: no worker can own a SYNCING row at
  that point. (2) Make rename carry sync state coherently: a file renamed
  while SYNCING ends at the new path DIRTY (or is requeued there), and the
  worker's refused publish on the old path does not strand anything.
  Follow the generation rule in AGENTS.md (no read-modify-write of
  `sync_status`).
- **Non-goals:** no change to the monitor's polling design (#17), no
  per-directory locking (#61).
- **Owned scope:** `storage/state.py`, `storage/fs.py` (`init` and
  `rename`), `storage/namespace.py` (rename), `storage/sync_executor.py` if
  the refused-publish requeue needs the new path, and their tests
  (`tests/test_state.py`, `tests/test_fs_core_integration.py`,
  `tests/test_state_rename.py`, `tests/test_sync_system.py`).
- **Dependencies:** `publish_sync_status` / `mark_dirty` and the descriptor
  bookkeeping in `rename()` (merged in #99).
- **Acceptance criteria:** a database with SYNCING rows opened by a fresh
  mount has them DIRTY before the first monitor pass, with their generation
  and checksum intact; a rename during an in-flight sync ends with the new
  path synced (system test through `SyncManager` workers against local
  members, with a backend whose `copy_from_local` blocks on an event); the
  old path leaves no row and no `file_locations` entry; tests pinning the
  fixes are mutation-checked.
- **Boundary tests:** `tests/test_sync_system.py` and
  `tests/test_state_rename.py` keep passing unchanged.
- **Budget:** one lane session.
- **Authority:** as WP-074.
- **Worker bound:** two Implementer-tier workers at most.
- **Evidence:** as WP-074.
- **Stop conditions:** the same test failing three distinct ways; any need
