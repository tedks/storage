# Contract for late directory additions in Nautilus v0 (proposed)

**Owner.** Storage desktop integration. **Consumers.** Mount change-feed producer and process-scoped Nautilus adapter.

This slice specializes the [desktop listing changes contract](desktop-listing-changes.md) for a native `file://` directory on an explicitly selected Storage mount. A desktop poll must never start a remote listing, fetch file contents, mutate a file, or hold a FUSE callback waiting for a client. The tracer loads a process-scoped `LD_PRELOAD` adapter in the isolated Nautilus process to deliver events on its original GIO monitors. It changes neither the installed GLib libraries nor the kernel. General installation requires compatibility checks and an explicit removal path.

**Producer.** Commit the merged listing, make the child visible to a client lookup through the kernel, then publish. An empty or failed member contributes no additions. An obsolete enumeration cannot publish into a newer one. Duplicate discoveries of a child already present in the union do not represent another addition. If freshness cannot be established, signal that reconciliation is required. The tracer requires progressive listings and `negative_timeout=0`; configurations that cache negative lookups or stale directory results need an equivalent visibility guarantee before delivery.

**Transport and discovery.** The tracer enables the producer explicitly with `STORAGE_EXPERIMENTAL_DESKTOP_ADDITIONS=1`. The adapter gets the selected mount and its private Unix control socket explicitly through `STORAGE_NAUTILUS_MOUNT` and `STORAGE_NAUTILUS_SOCKET`. Reuse the owner-private socket path in an owner-only directory with same-UID peer verification. An unsupported or unauthorized endpoint cannot establish interest.

**Request and reply.** The `desktop.additions.v1` operation uses the existing cache control protocol to poll one mount and directory. Both `mount_hex` and `directory_hex` encode native path bytes as hexadecimal. The mount path is absolute and canonical; the directory is relative to it (empty for the mount root). The initial poll uses integer `since_us`; continuation uses `generation` and `after`. A reply carries `status` (`ok`, `gap` or `generation-changed`), the mount `generation`, the last scanned sequence `through`, and `added`, an ordered list of hexadecimal basename strings. Visit each addition at most once per consumed cursor range. `gap` reports lost coverage and `generation-changed` requires a fresh baseline. Malformed requests and mismatched mount paths return control errors. Report unsupported operations and disconnects as failures. Do not advance a cursor over unverified coverage. The retained sequence is mount-wide, so eviction can conservatively signal a gap even in an unrelated directory. Advance through scanned history when no events match. Bound the tracer to 128 retained events, 768 native bytes per path, 255 bytes per basename and 16 active monitors; poll roughly every 500 ms and bound control message size and work per poll. Reject empty names, `.`, `..`, slash, NUL or invalid encoding before building a child location. Filenames stay out of status, metrics and logs outside the scoped reply.

**Initial coverage.** Capture `since_us` on the same boot-monotonic clock as the producer no later than the start of baseline enumeration. Replay retained discoveries committed at or after the marker, including timestamp ties, then continue from the returned sequence. A timestamp taken when constructing a monitor qualifies only if construction precedes or coincides with the baseline start. If ordering, clock comparability or retention is uncertain, reconcile the exact interested directory within bounded work or enter degraded state. A new mount generation requires a fresh baseline even when the mount path is reused.

**Client.** The Linux tracer requires the same mount namespace as the daemon. Verify component-wise containment in the selected, current mount instance before registration and queued delivery. Reject symlink traversal, `..`, prefix siblings, oversized paths, replaced mounts and paths crossing into a different mounted filesystem. Deliver on each monitor's owning main context. Never target a window by focus or active tab. Cancellation, navigation and destruction end interest in that monitor. Hold no dangling references during queued delivery. Unrecoverable gaps leave the adapter visibly degraded until a fresh baseline. A full refresh is safe only when it targets the exact interested directory.

**Acceptance.** With the first row visible in an isolated Nautilus instance, observe `ENOENT` for the held child's path, release its member, and observe the second row in the same view without manual action. An unrelated monitor stays quiet. Publish during initial attachment and verify delivery or an explicit gap, including timestamp ties. Exercise duplicate contributions, stale revisions, disconnect, gap, unusual basenames, paths that escape or cross the mount, monitor teardown and remount at the same path. The tracer can demonstrate individual boundaries before all release cases pass. Confirm the complete chain against the target Nautilus/GIO pair before recommending installation.
