## Candidate 1: foreground admission and channel classification

The small-looking change starts with the channel tracer `48b5ea0` (`storage/backends/base.py`, `storage/cache.py`, `storage/fs.py`), the active callback gate `2a5490c` (`storage/foreground_admission.py`, `storage/fs.py`, `storage/cli_mount.py`, `storage/mount_profiles.py`, `storage/BUILD`), then the actual warm-open/directory protection and transfer `05401f8`, `e53cb50`, `22379e2` (`storage/fs.py`, admission, tests and contracts). `CacheManager.fetch_into_cache` encloses `copy_to_local` in `bulk_request`; `StorageFS.__call__` marks callbacks interactive; `storage/backends/ssh_pool.py:762-835` reserves capacity only from bulk leases. `StorageFS._foreground_class` distinguishes metadata (`opendir`/`readdir`), demand (`read` and cached `open`) and ordinary cold `open`; `open` releases path/namespace locks and its demand slot before ordinary admission when the cache disappears. The latter is essential: waiting for ordinary while holding a path lock can deadlock an admitted cold opener on that path. Metadata browsing and warm reads retain protected Python admission; full copies cannot consume every SSH channel *as bulk*. The reserve does not bound native threads or guarantee a free channel if other interactive operations occupy all channels.

This cut would omit sync worker growth and all Stage1 scratch authority (`37d671b`, `b0c0c4f`), so it would not meet Ted's complete demand-growth request. More seriously, these first admission commits used an opener-private refetch pin: a changed A observed before the lock-free admission transfer could be lost or a concurrent opener could select stale B. `34c584a` introduced shared per-member debt; the ensuing stream, full-fetch, local-mutation and namespace fixes are substantive dependencies, not optional polish. Current calls run `_revalidate_cached_file` and `_ensure_file_in_cache` under `open`'s path lock (`storage/fs.py:2111-2250, 2442-2540, 2908-2990`), with `cache_file -> fetch_into_cache` installing a staged inode and publishing a row/baseline. A cut that only changes admission allows a late fetch/stream to install stale B after A's observation or after local bytes changed; no-replace alone cannot reject a stage when the final path is absent. Concurrent write/O_TRUNC/create and partial rename can also make a row or descriptor belong to the wrong inode. These races were exposed/amplified by threaded admission; the underlying fetch/write and namespace interfaces predate it. The mount-lifetime fixes in `34c584a`, `e780b4a`, `19dc97c`, `14c5469` and their intermediate repair commits are coupled to the publication boundary. The proposed durable debt and negative-prefix replay is still absent; the two restart schedules remain deferred. Current incomplete member rename can leave reads at either prefix EIO and uploads blocked indefinitely. That is a known release blocker, not a harmless out-of-scope behavior. A safe shipping extraction therefore cannot be this small cut on the current source baseline.

Minimum repair/proof before considering this candidate: shared path-scoped generation and independent member debts survive the admission wait and cancellation; full/stream no-replace commit validates token, exact inode, local epoch and DIRTY before bytes become visible; namespace move and sync guards retain source/target identity and lazy descendant denial; crash/restart cannot forget debt/denial. The published v3 freshness, subtree and durable contracts spell out those obligations. Pulling all of them into this cut defeats the separation objective and still needs member-name reconciliation. `bcf062a`'s retry fence would prevent one destructive queued retry, but it neither restores reads nor replaces reconciliation and is not landed.

## Candidate 2: bounded background sync growth

The growth series is `afd5318` (`storage/sync.py` and manager tests), `630b76d` (mount/profile/FS/config), `cc70ba6` (growth and SSH ceilings), `effadd7` (partial startup/invalid mount cleanup) and `1f96002` (stable remote identity/display-name port). `SyncManager._maybe_grow` targets distinct active plus queued demand up to configured `max_workers`; idle extras retire; stop preserves real queue entries and prevents restart over lingering workers (`storage/sync.py:180-360, 410-505`). The intended cap is eight with SSH/rsync members, 32 local-only. This is closely related to #167's `d61bdb1`; #167 remains a draft held for scope and has mount/profile conflicts with newer master. A later owner must explicitly coordinate succession, not treat either branch as an automatic merge of the other.

This cut can be **implemented and reviewed separately as sync capacity**, with the feature off when `max_sync_workers` is absent, but it preserves no new foreground admission: metadata, warm reads and cold opens still contend in the old FUSE loop, and cold opens can hold all four interactive SSH channels. The cut cannot be advertised as Ted's responsiveness mission. More workers also make the preexisting upload/write/rename interleavings likelier; they do not create the namespace identity bug, but a queued legacy directory retry can destructively mutate an occupied member name after a newer partial rename. The later `54a7812`/`e87487b`/`bcf062a` fence contains that retry on PR #171 only and is unlanded; shipping growth cannot assume it. Minimum independent safety work is an exact-base comparison of sync task identity, generation-checked status, upload locks, stop/restart and actual old-name retry behavior, plus a scoped pre-I/O retry guard or equivalent proved boundary if that race is reachable. The guard is still non-shipping for incomplete rename recovery. Sync growth must also leave `remote0` stable, display labels separate and `UpdateHostKeys=no`.

## Recommendation and rollback

The next bounded package should be **source/test planning only** for an exact-base foreground extraction: choose the eventual accepted base, map the smallest full-fetch/stream/mutation/namespace and restart safety dependencies, and write a short executable same-schedule test selector before any code port. Stop if that selector still requires the unresolved member-lineage/product boundary; do not build a new persistence API to force the split. Rollback for a later reversible extraction is to drop its opt-in foreground/config commits before release, leaving the accepted baseline and #167 untouched.
